# OpenCode en parallèle de Claude Code — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** installer OpenCode (CLI + desktop) via Homebrew, configuré par home-manager pour utiliser Claude via le provider Claude Agent, en partageant instructions, skills, subagent, MCP, deny list, rtk, claude-mem et superpowers avec Claude Code, sans changer la config effective de Claude Code.

**Architecture:** le contenu partagé passe dans `agents/` à la racine du repo, et les définitions Nix partagées (serveurs MCP) dans un module `nix/home/agents.nix`. `claude.nix` est recâblé sur ces sources sans changement de rendu. `opencode.nix` symlinke ce qui peut l'être et génère le reste au switch par des scripts d'activation : fusion jq dans un `opencode.json` modifiable, traduction des subagents, copie des skills de plugins, plugin rtk.

**Tech Stack:** Nix flake + home-manager (dans `nix/`), Homebrew via `nix/home/homebrew.nix`, bash, jq, yq-go, rsync, OpenCode 2.2.3+.

**Spec:** `docs/superpowers/specs/2026-10-31-opencode-design.md`

## Global Constraints

- OpenCode `>= 2.2.3` : formula `opencode` (homebrew/core) et cask `opencode-desktop`.
- La config effective de Claude Code ne change pas : `diff -r -B` entre les snapshots avant et après (Task 1) doit être vide à la fin de chaque tâche.
- `permissions` OpenCode : `{"action":"*","resource":"*","effect":"allow"}` en premier, puis une règle `deny` par entrée `Bash(…)`, `Read(…)`, `Edit(…)` de `.permissions.deny` de `nix/home/claude/settings.json`. La dernière règle qui matche gagne.
- Modèles attendus (à confirmer en Task 3) : `claude-agent/claude-opus-5-5#xhigh` (principal), `claude-agent/claude-sonnet-5-5` (subagents), `claude-agent/claude-haiku-5-5` (titres).
- `~/.config/opencode/opencode.json` n'est jamais un symlink. Les clés gérées par Nix sont écrasées, les autres conservées.
- `rm -rf` est refusé à l'agent : toute suppression récursive est une commande donnée à l'utilisateur.
- Les scripts d'activation n'échouent jamais le switch pour une source absente : un message sur stderr, puis `exit 0`.
- Les fichiers Nix nouveaux sont `git add` avant tout `nix build`, sinon le flake ne les voit pas. `agents/` est hors du flake (`nix/`) : il n'est lu qu'au runtime, par chemin `config.dotfiles.dir`, jamais comme chemin Nix.
- Markdown sans retour à la ligne en dur. Commentaires de code : aucun par défaut.
- Travail sur la branche `opencode`, dans le working tree principal : les symlinks out-of-store pointent sur lui, un worktree ne servirait à rien.

## Review Focus

1. Un `drs` relancé après l'installeur claude-mem conserve `mcp["claude-mem"]`, et deux `drs` de suite laissent `opencode.json` identique. Le test va en Task 3, step 6.
2. Sur la machine `boulot`, où OpenCode n'est pas encore connecté et les plugins Claude parfois absents, chaque script se contente d'un message et le switch passe. Le test, avec un HOME vide, va dans les Tasks 3, 4 et 5.
3. Si `opencode.json` contient du JSON invalide après une édition à la main, le fichier n'est pas écrasé et le switch passe avec un message. Le test va en Task 3, step 6.
4. Un skill de plugin peut porter le même nom qu'un skill de `~/.claude/skills`, `synced/` compris. Dans ce cas, pas de doublon dans OpenCode : le skill du plugin est ignoré avec un message. Le test va en Task 4, step 4.
5. Quand Claude met à jour un plugin, son chemin dans le cache change. Les chemins de superpowers et des skills sont donc re-résolus à chaque switch. Si le chemin de claude-mem n'existe plus, un message donne la commande à relancer. Le test va en Task 5, step 5.

- [ ] **Step 2: Écrire `merge-config.jq` et `opencode-merge-config`**

`merge-config.jq` reçoit `$servers` (slurpfile, JSON de l'option MCP traduite en `{ type = "local"; command = [ s.command ] ++ s.args; environment = s.env; }`), `$settings` (slurpfile, `nix/home/claude/settings.json` du repo), `$home`, `$opencodeSrc` et `$superpowers`, puis :

```jq
. + {
  "$schema": "https://opencode.ai/config.json",
  autoupdate: false,
  model: "claude-agent/claude-opus-5-5#xhigh",
  instructions: ["\($home)/.claude/RTK.md", "\($opencodeSrc)/AGENTS.opencode.md"],
  plugins: [$superpowers],
  permissions: ([{action: "*", resource: "*", effect: "allow"}]
    + [$settings[0].permissions.deny[]
       | capture("^(?<tool>Bash|Read|Edit)\\((?<resource>.*)\\)$")
       | {action: ({Bash: "bash", Read: "read", Edit: "edit"}[.tool]), resource, effect: "deny"}])
}
| .agents = ((.agents // {}) * {
    title: {model: "claude-agent/claude-haiku-5-5"},
    general: {model: "claude-agent/claude-sonnet-5-5"},
    explore: {model: "claude-agent/claude-sonnet-5-5"}
  })
| .mcp = ((.mcp // {}) + $servers[0])
```

Le script `opencode-merge-config` suit le modèle de `claude-merge-mcp-servers` : il crée `{}` si le fichier est absent. Si `jq empty` échoue, il affiche `opencode: ~/.config/opencode/opencode.json n'est pas du JSON valide, fusion ignorée` et sort avec `exit 0`. Il écrit dans un fichier temporaire, puis fait `cmp -s || mv`. `$superpowers` vaut `.plugins["superpowers@claude-plugins-official"][0].installPath` de `~/.claude/plugins/installed_plugins.json` si ce dossier contient `index.js`, sinon `superpowers@git+https://github.com/obra/superpowers.git`. Dans `opencode.nix` : `home.file.".config/opencode/AGENTS.md"` -> `mkOutOfStoreSymlink "${config.dotfiles.dir}/agents/AGENTS.md"`, et `home.activation.opencodeConfig = lib.hm.dag.entryAfter [ "writeBoundary" ] "$DRY_RUN_CMD ${mergeConfig}"`.
